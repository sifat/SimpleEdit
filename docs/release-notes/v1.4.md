## Java, PHP and SQL highlighting

**Java** — `.java`. Class and type names are coloured from where they appear, not guessed from capitalisation, so they are coloured here where JavaScript's and Python's are not. Method names are functions; `this` and `super` are keywords.

**PHP** — `.php`, `.phtml`. A PHP file is two documents at once, and both are coloured: the PHP between `<?php … ?>`, and the HTML around it — including that HTML's own `<style>` and `<script>`. The HTML is parsed as **one document with holes in it**, not as a series of fragments, so a `<div>` opened above a `<?php` and closed below the `?>` is one element, and the PHP echoed inside an attribute value keeps its own colour. Variables are coloured, sigil included.

**SQL** — `.sql`. Keywords, strings, numbers, types, column and table names, functions. Hand-written SQL parses cleanly.

### Worth knowing

- **mysqldump and phpMyAdmin exports are barely highlighted.** The only SQL grammar available leans ANSI and PostgreSQL; MySQL's `/*!40101 … */` directives, `ENGINE=InnoDB`, `COLLATE` in column definitions and `LOCK TABLES` all parse as errors. Most dumps are far past the size limit and open plain anyway.
- **The app is bigger.** SQL's grammar alone is 11 MB per architecture; the universal binary went from about 12 MB to 34 MB.
- **Size limits:** SQL files up to 32 KB are highlighted — half everything else, because the expensive SQL file is a dump, not dense code. PHP and Java keep the 64 KB limit.
- **PHP's grammar rejects a few valid names** — `const FALSE`, `"$obj->class"` inside a string, a global `function readonly()` — a handful of characters in 5 of 45,000 real files. The alternative could not parse any enum containing a `const`.

## Fixed

- **Undo could never make a document clean again.** Every keystroke was counted twice and every undo netted to zero, so typing one character and undoing it left the dirty dot on and made Close ask whether to save a file identical to disk.
- **Pasting Windows text into a Unix file** left carriage returns in the buffer and wrote them straight through on save — a mixed-ending file, the exact thing the line-ending handling exists to prevent. Every insertion is normalised now.
- **Line numbers drifted** after a pasted carriage return or paragraph separator; the gutter counted only `\n` while the text system breaks paragraphs on more than that.
- **A file the editor could not save in its own encoding** — a Latin-1 file with an emoji typed into it — silently became UTF-8, and then silently went back on the next save. It now stays UTF-8 and the app knows it.
- **A hostile inline `<script>`** — deep nesting, an unbalanced bracket — cost the full time budget on every keystroke, because a budget cut inside an embedded language was never reported to the backoff that exists to space those attempts out.
- **Minify JSON** left wrapping on for the one-enormous-line document it produces; **Format JSON** parsed the document twice.

## Install

```sh
unzip SimpleEdit.zip
mv SimpleEdit.app /Applications/
xattr -dr com.apple.quarantine /Applications/SimpleEdit.app
open /Applications/SimpleEdit.app
```

**The `xattr` line is required.** The app is ad-hoc signed, so macOS reports *"SimpleEdit is damaged and can't be opened"* without it — that means "not signed by a registered developer", not corrupted.

Universal binary: Apple Silicon and Intel.

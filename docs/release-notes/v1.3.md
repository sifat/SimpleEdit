## Python and shell highlighting

**Python** — `.py`, `.pyi`, `.pyw`. Type annotations are coloured as types, decorators and calls as functions, attributes and methods as properties, and f-strings as a single string.

**Shell** — `.sh`, `.bash`, `.zsh`, `.command`, **and shell dotfiles by name**: `.zshrc`, `.bashrc`, `.bash_profile`, `.profile`, `.zprofile` and the rest. A dotfile has no file extension, so these used to stay plain; they're now the shell files most likely to open coloured. Commands, their flags, variables, strings and heredocs are all highlighted, and a command inside `$(…)` keeps its own colour.

### Worth knowing

- **zsh** is parsed with the Bash grammar, so zsh-only syntax (glob qualifiers and the like) stays plain.
- A script with **no extension**, recognisable only by its `#!/bin/bash` line, isn't detected yet.
- **Class names** in Python stay plain, as in JavaScript, and Python's **word operators** (`and`, `or`, `not`, `in`) are grey like other operators.
- **Size limits** are unchanged: Python and shell files up to 64 KB are highlighted.

### Changed

- When two highlighting rules claim exactly the same text, the weaker one now loses, instead of leaving the result to chance. One visible effect in existing files: `const MIN_SIZE = () => 1` in JavaScript is now coloured as the function it is.

## Install

```sh
unzip SimpleEdit.zip
mv SimpleEdit.app /Applications/
xattr -dr com.apple.quarantine /Applications/SimpleEdit.app
open /Applications/SimpleEdit.app
```

**The `xattr` line is required.** The app is ad-hoc signed, so macOS reports *"SimpleEdit is damaged and can't be opened"* without it — that means "not signed by a registered developer", not corrupted.

Universal binary: Apple Silicon and Intel.
